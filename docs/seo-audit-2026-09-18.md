Date: 18 September 2026. Scope: all local public pages, supporting content, technical indexing and links. Audience assumption: English-speaking D2C founders/operators, with India-relevant COD and INR examples, plus teams researching AI marketing workflows. This is an implemented launch foundation, not evidence of rankings, traffic growth or sales.

## Critical live finding

- The apex domain redirects to the www domain.

The live version blocks search discovery/indexing. The local production build now emits indexable pages, populated sitemap and canonical URLs, but these changes have **not been deployed**. Merely editing this repository does not fix the currently served production responses. Recheck after deploying. No Search Console account was accessed or verified.

## Research method and limits

Reviewed current search results for Shopify CRO services, COD confirmation/order automation, AI marketing workflows, RTO calculators, unit economics and related planning tools. Checked first-party Shopify material, directly competing service/tool pages for naming and intent, and Google Search Central for implementation. Search-result wording helps identify intent; it is not keyword-volume or difficulty measurement. No Google Ads Keyword Planner, Search Console history, Ahrefs or Semrush account data was available. Do not present these targets as validated traffic forecasts.

Prioritise the three specific service themes and calculator searches. Broad “AI agency” terms are less specific to the actual offer. Skill Manager remains a prerelease product, so its page targets product discovery, not purchase intent. Pricing and About support evaluation rather than competing with service pages for the same head term. Existing URLs were retained to avoid unnecessary migration.

## Implemented changes

- Unique, descriptive titles and descriptions for every indexable page, with matching social metadata. Removed the irrelevant global meta-keyword list.
- Explicit primary headings describing the page topic. Service headings retain readable, responsive layouts.
- One central route/metadata inventory drives the sitemap. Canonicals omit tracking parameters and trailing slashes; www remains the existing production origin. Invalid custom origins fail rather than publishing broken canonical URLs.
- Connected Organization, WebSite, WebPage, BreadcrumbList and service-specific Service schema. Guides also contain Article schema matching visible titles, publisher and publication date. No invented ratings, client results, product prices or purchase availability.
- Visible breadcrumbs with working parent links. Cross-links connect guides, calculators, service pages and pricing. Guides are linked from the home page and footer.
- Nine service-specific questions with native details controls. Six calculators now have static instructions, original numeric examples and explicit limitations, plus links to relevant services and guides.
- Three original practical guides and a guide index. These are educational checklists/scenarios, not manufactured case studies or copied competitor articles.
- Corrected tool summaries: RTO direct costs are separate from sales value; runway uses a monthly balance projection; unit-economics wording includes its actual cost inputs.
- Existing text, FAQs, navigation and guides render in HTML. Calculators retain a no-JavaScript explanation; the interactive calculations require JavaScript.
- Kept image descriptions and dimensions; made the below-fold product illustration lazy-loaded. No new third-party tracking, fonts, or SEO dependencies were introduced.
- Dedicated noindex 404 page with useful recovery links, excluded from sitemap and schema.
- Production robots allow crawling; preview builds are noindex with an empty sitemap and disallowed crawling. Vercel preview/development tiers are detected at build time; `PUBLIC_SITE_INDEXABLE=false` is available for other staging environments. Keep private staging behind hosting access protection as well.
- Vercel trailing-slash configuration matches canonical URL format. No DNS/account settings were changed.
- Optional Search Console HTML-verification token support (`PUBLIC_GOOGLE_SITE_VERIFICATION`). This does not itself verify ownership or submit the sitemap.
- Removed the misleading rebuild timestamp used as every page's sitemap last-modified time. No lastmod is emitted until maintained content-level dates are available. Google ignores priority/changefreq, so those were removed.
- Added `npm run test:seo` to inspect actual emitted HTML, metadata, sitemap, schema, local links/anchors/assets and image dimensions after build.

## Production release steps

1. Deploy this reviewed local version to the existing production project. Production must not have `PUBLIC_SITE_INDEXABLE=false`; set `PUBLIC_SITE_URL=https://www.mlabsgrowth.com` if overriding the default. Vercel should expose its normal system deployment-tier variables.
2. Request the homepage, all indexable routes, robots and sitemap from the live host. Confirm HTTP 200 for valid pages, HTTP 404 for a missing route, canonical www URLs, no production noindex header/meta and no crawler-blocking authentication. Confirm slash redirects on the real host.
3. Verify the domain in Google Search Console using DNS or the provided HTML-verification setting. Submit `https://www.mlabsgrowth.com/sitemap.xml`; inspect the home page, three service pages, a guide and a calculator. Use Rich Results Test on breadcrumb and Article markup. Rich appearance is not guaranteed.
4. Measure mobile loading and interaction on the deployed version with PageSpeed Insights and subsequently Search Console field data. Prioritise actual LCP/INP/CLS regressions; local layout checks are not field performance evidence.
5. Complete the separately documented Calendly intake and completed-booking measurement setup. Judge SEO by relevant enquiries and qualified calls as well as impressions/clicks. UTM forwarding is not completed-conversion analytics.
